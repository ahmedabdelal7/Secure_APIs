Student API · Security Design

Defining Security Boundaries
for Student Endpoints

Overview
Security boundaries define who may access each API endpoint and which actions they are allowed to perform. They are designed before implementing authentication, JWT, and authorization so every endpoint has a clear access policy.

1 · Start with the endpoint inventory

MethodEndpointPurpose
GET/api/Students/AllRetrieve all students
GET/api/Students/PassedRetrieve passed students
GET/api/Students/AverageGradeRetrieve average grade
GET/api/Students/{id}Retrieve one student
POST / PUT / DELETE/api/Students[/{id}]Create, update, or delete

2 · Classify endpoints by risk

RiskEndpointsWhy it matters
HIGHPOST, PUT, DELETEChange or destroy records; can corrupt student data or grades.
MEDIUMGET /All, GET /{id}May expose identities, personal information, and grades.
LOW*GET /Passed, GET /AverageGradeAggregated results can be public when they reveal no sensitive information.

*Important: Read-only does not automatically mean safe. Review the actual response data before making an endpoint public.

3 · Assign access policies

ADMIN ONLY

Create, update, and delete student records. Requires an authenticated administrator.

AUTHENTICATED STUDENT

View their own record only. The requested student ID must match the authenticated user's identity.

PUBLIC

View passed-student results and average grade, provided the response contains no sensitive data.
